# ValutaTrade Hub

Консольное приложение для симуляции торговли валютами. Позволяет регистрироваться,
входить в систему, покупать и продавать валюты, просматривать портфель и получать
курсы из локального кеша. Отдельный сервис парсинга обновляет курсы через
CoinGecko и ExchangeRate-API.

## Демонстрация

[Посмотреть демонстрацию работы ValutaTrade Hub](https://asciinema.org/a/CpPm057RAcQhP14U)

## Требования

- Python 3.12 или новее.
- uv.
- Подключение к интернету для обновления курсов.
- API-ключ ExchangeRate-API для загрузки фиатных курсов.

## Установка и запуск

Склонируйте репозиторий и перейдите в корень проекта.

Установите зависимости:

```text
uv sync
```

Создайте в корне проекта файл `.env`:

```dotenv
# API-ключ для получения курсов фиатных валют
EXCHANGERATE_API_KEY=your_api_key
```

Замените `your_api_key` своим ключом из личного кабинета
[ExchangeRate-API](https://www.exchangerate-api.com/).
Ключ также можно передать через переменную окружения `EXCHANGERATE_API_KEY`.
Файл `.env` с настоящим ключом не добавляйте в репозиторий.
Для используемого публичного запроса CoinGecko ключ не требуется.

Запустите приложение:

```text
uv run valutatrade
```

После запуска вводите команды в приглашении «Введите команду».
Сначала загрузите курсы:

```text
update-rates
show-rates
```

Для завершения работы:

```text
exit
```

Запускайте приложение из корня проекта: здесь читаются `pyproject.toml` и `.env`,
а пути к данным и логам считаются относительно текущей рабочей папки.
Настройки и ключ загружаются при запуске; после их изменения перезапустите приложение.

## Поддерживаемые валюты

| Код | Валюта           |
| --- | ---------------- |
| USD | Доллар США       |
| EUR | Евро             |
| GBP | Британский фунт  |
| RUB | Российский рубль |
| BTC | Bitcoin          |
| ETH | Ethereum         |
| SOL | Solana           |

CoinGecko предоставляет курсы BTC, ETH и SOL, ExchangeRate-API — EUR, GBP и RUB.
Парсер сохраняет пары вида `BTC_USD` и `EUR_USD`.
Обратные и перекрёстные курсы рассчитываются по этим значениям.
Курс валюты к самой себе равен единице.

## Команды

Для `register`, `login`, `buy`, `sell`, `get-rate` и `update-rates`
используйте порядок аргументов из примеров.

### Регистрация

```text
register --username alice --password 1234
```

Имя должно быть непустым и уникальным. Пароль — не короче четырёх символов.
При регистрации создаются пользователь и пустой портфель.
Пароль сохраняется в виде SHA-256-хеша с индивидуальной солью.

### Вход

```text
login --username alice --password 1234
```

После успешного входа приложение запоминает пользователя до завершения работы.
При следующем запуске нужно войти заново.

### Просмотр портфеля

```text
show-portfolio
show-portfolio --base EUR
```

Выводятся балансы кошельков, их стоимость в базовой валюте и общая стоимость портфеля.
База по умолчанию задаётся настройкой `default_base_currency` — в примере конфигурации USD.
Команда доступна после входа. Для пересчёта нужны свежие курсы в кеше.

### Покупка валюты

```text
buy --currency EUR --amount 10
```

`amount` — количество покупаемой валюты. Стоимость списывается с USD-кошелька.
Кошелёк покупаемой валюты создаётся автоматически, если его ещё нет.
Выводятся использованный курс, стоимость покупки и баланс валюты до и после сделки.

Для покупки необходимо войти в систему, иметь достаточно USD и свежий курс.
Покупка USD за USD запрещена. Сумма должна быть положительным конечным числом.

### Продажа валюты

```text
sell --currency EUR --amount 5
```

`amount` — количество продаваемой валюты. Валюта списывается с соответствующего
кошелька, выручка начисляется на USD-кошелёк. Если USD-кошелька нет, он создаётся.
Выводятся использованный курс, выручка и баланс валюты до и после сделки.

Для продажи необходимо войти в систему, иметь достаточно продаваемой валюты
и свежий курс. Продажа USD за USD запрещена.
Сумма должна быть положительным конечным числом.

### Получение курса

```text
get-rate --from USD --to BTC
get-rate --from GBP --to SOL
```

Выводятся прямой курс, время его обновления и обратный курс.
Вход в систему не требуется. Коды валют можно вводить в нижнем регистре.

Команда читает локальный кеш и не обращается к API.
Срок свежести задаётся `rates_ttl_seconds` — в примере 300 секунд.
Если нужного курса нет или он устарел, приложение предлагает выполнить `update-rates`.
Для перекрёстного курса проверяется свежесть обоих исходных курсов.

### Обновление курсов

```text
update-rates
update-rates --source coingecko
update-rates --source exchangerate
```

Без `--source` опрашиваются оба источника. Вход в систему не требуется.
Результат содержит количество обновлённых курсов и время обновления в UTC.

Если один источник недоступен, курсы другого сохраняются, а прежние записи
недоступного источника остаются в кеше. Приложение сообщает о частичном отказе
и указывает путь к журналу ошибок. Сохранение старой записи не продлевает её TTL.

Если получить курсы не удалось ни от одного источника, кеш и история не обновляются.
Без ключа ExchangeRate-API можно загрузить криптовалютные курсы через CoinGecko.

### Просмотр кеша курсов

```text
show-rates
show-rates --currency RUB
show-rates --top 2
show-rates --base EUR
show-rates --currency BTC --base EUR
```

- `--currency` — показать курс выбранной валюты.
- `--top` — показать N самых дорогих криптовалют; N должно быть положительным целым числом.
- `--base` — пересчитать отображаемые курсы относительно выбранной базы; по умолчанию USD.

Параметры можно сочетать. Без `--top` записи сортируются по названию пары,
с `--top` — по убыванию курса среди криптовалют.
В заголовке показывается `last_refresh` кеша.

Команда показывает сохранённый снимок без сетевых запросов, в том числе старые записи.
`last_refresh` обозначает время обновления снимка: при частичном отказе отдельные пары
могут быть старше. Для сделок и `get-rate` свежесть проверяется отдельно.

Если кеш отсутствует или пуст, приложение предлагает выполнить `update-rates`.
Если запрошенной валюты нет в кеше, выводится сообщение об отсутствии курса.

## Подготовка баланса для проверки

После регистрации портфель пустой. Команды пополнения USD в текущей версии нет.

Для проверки сделок:

1. Зарегистрируйте тестового пользователя и запомните его ID.
2. Завершите приложение.
3. Откройте файл из настройки `portfolios_path` — в примере `data/portfolios.json`.
4. Найдите объект портфеля с этим `user_id`.
5. Добавьте в его пустой словарь `wallets` USD-кошелёк.

Например, для пользователя с ID `3` запись должна выглядеть так:

```json
{
    "user_id": 3,
    "wallets": {
        "USD": {
            "balance": 100.0
        }
    }
}
```

Используйте ID своего пользователя. Это один элемент списка в `portfolios.json`:
сохраните внешние квадратные скобки файла и портфели остальных пользователей.

Запустите приложение, войдите под тестовым пользователем и выполните:

```text
update-rates
show-portfolio
buy --currency EUR --amount 1
show-portfolio
sell --currency EUR --amount 1
show-portfolio
```

При неизменном курсе покупка и последующая продажа одинакового количества валюты
восстанавливают исходные балансы. Значения в выводе округляются для отображения.

## Настройки

Основные настройки находятся в секции `[tool.valutatrade]` файла `pyproject.toml`:

| Ключ                    | Назначение                     | Значение в конфигурации |
| ----------------------- | ------------------------------ | ----------------------- |
| `users_path`            | Файл пользователей             | `data/users.json`       |
| `portfolios_path`       | Файл портфелей                 | `data/portfolios.json`  |
| `rates_path`            | Кеш для Core Service           | `data/rates.json`       |
| `rates_ttl_seconds`     | Срок свежести курса в секундах | `300`                   |
| `default_base_currency` | База портфеля без `--base`     | `USD`                   |
| `log_path`              | Файл логов                     | `logs/actions.log`      |
| `log_level`             | Уровень логирования            | `INFO`                  |
| `log_format`            | Обозначение текстового формата | `text`                  |

Загрузчик не подставляет эти значения автоматически при отсутствии ключей.
`SettingsLoader` загружает настройки один раз.
`DatabaseManager` получает пути из настроек и выполняет чтение и сохранение JSON.
Оба класса реализованы как Singleton.
Базовая валюта отображения портфеля не меняет валюту расчёта сделок — USD.

Параметры парсера находятся в `valutatrade_hub/parser_service/config.py`:

| Параметр               | Назначение                          | Значение                                        |
| ---------------------- | ----------------------------------- | ----------------------------------------------- |
| `EXCHANGERATE_API_KEY` | Ключ из окружения или `.env`        | Задаётся пользователем                          |
| `REQUEST_TIMEOUT`      | Таймаут запроса в секундах          | `10`                                            |
| `BASE_CURRENCY`        | База запросов к API                 | `USD`                                           |
| `FIAT_CURRENCIES`      | Фиатные валюты                      | `EUR, GBP, RUB`                                 |
| `CRYPTO_CURRENCIES`    | Криптовалюты                        | `BTC, ETH, SOL`                                 |
| `CRYPTO_ID_MAP`        | Соответствия тикеров и ID CoinGecko | `BTC: bitcoin, ETH: ethereum, SOL: solana`      |
| `COINGECKO_URL`        | Эндпоинт криптовалютных курсов      | `https://api.coingecko.com/api/v3/simple/price` |
| `EXCHANGERATE_API_URL` | Базовый URL фиатного API            | `https://v6.exchangerate-api.com/v6`            |
| `RATES_FILE_PATH`      | Кеш, записываемый парсером          | `data/rates.json`                               |
| `HISTORY_FILE_PATH`    | История полученных курсов           | `data/exchange_rates.json`                      |

`RATES_FILE_PATH` парсера и `rates_path` Core должны указывать на один файл.
Обновление запускается вручную командой `update-rates`.

## Валюты и ошибки

Валюты представлены абстрактным классом `Currency` и наследниками
`FiatCurrency` и `CryptoCurrency`. Реестр `CURRENCIES` и функция `get_currency()`
находятся в `core/currencies.py`. Коды при поиске приводятся к верхнему регистру.

В `core/exceptions.py` определены:

- `InsufficientFundsError` — недостаточно средств; сообщение содержит доступную и требуемую суммы.
- `CurrencyNotFoundError` — неизвестная валюта; CLI дополнительно показывает поддерживаемые коды.
- `ApiRequestError` — ошибка запроса к внешнему API или некорректное значение полученного курса.

Недопустимые суммы, отсутствие или истечение срока свежести курса
и некорректные данные хранилища обрабатываются через `ValueError`.

## Логирование

При запуске CLI настраивается запись в файл из `log_path`,
по умолчанию `logs/actions.log`. Папка создаётся автоматически.
Используется текстовый формат и уровень `INFO`.
`log_format` сейчас не переключает форматирование; JSON-формат не реализован.

Декоратор `@log_action(verbose=True)` подключён к покупке и продаже.
Записи содержат время, действие, пользователя, валюту, количество, базовую валюту
и результат. При успехе добавляются курс и балансы до и после сделки.
При ошибке записываются её тип и сообщение; исключение передаётся дальше в CLI.

Парсер пишет в тот же журнал: начало обновления, результат каждого источника
и количество сохранённых курсов.

Пример записи сделки:

```text
INFO 2026-10-25T16:38:22 BUY user='alice' currency='EUR' amount=1.0 rate=1.1 base='USD' result=OK balance_before=10.0 balance_after=11.0
```

Лимит файла — 1 000 000 байт. Ротация сохраняет до трёх резервных файлов:
`actions.log.1`, `actions.log.2`, `actions.log.3`.
Логи исключены из Git через `logs/` в `.gitignore`.

## Хранение данных

При стандартных настройках используются:

- `data/users.json` — пользователи, хеши паролей, соли и даты регистрации.
- `data/portfolios.json` — портфели и балансы кошельков.
- `data/rates.json` — последние курсы по парам и время обновления снимка.
- `data/exchange_rates.json` — история полученных курсов.

Пример структуры кеша с учебным значением курса:

```json
{
    "pairs": {
        "EUR_USD": {
            "rate": 1.12,
            "updated_at": "2026-10-26T08:00:00+00:00",
            "source": "ExchangeRate-API"
        }
    },
    "last_refresh": "2026-10-26T08:00:01+00:00"
}
```

История — список записей с полями `id`, `from_currency`, `to_currency`,
`rate`, `timestamp` и `source`. Идентификатор составляется из пары и времени;
записи с уже существующим ID пропускаются.

Парсер сохраняет кеш и историю атомарно для каждого файла:
сначала записывает временный файл, затем заменяет целевой.
Для каждой пары в кеше сохраняется запись с более свежим временем.
Время парсера записывается в UTC с часовым поясом.

Пользователи, портфели и курсы сохраняются между запусками приложения.

## Структура проекта

```text
valutatrade_hub/
├── logging_config.py  # формат, уровень и ротация логов
├── decorators.py      # декоратор log_action
├── core/
│   ├── currencies.py  # иерархия и реестр валют
│   ├── exceptions.py  # пользовательские исключения
│   ├── models.py      # User, Wallet, Portfolio
│   ├── utils.py       # JSON, преобразования и валидаторы
│   └── usecases.py    # регистрация, вход, сделки, сводка и чтение кеша
├── infra/
│   ├── settings.py    # Singleton SettingsLoader
│   └── database.py    # Singleton DatabaseManager
├── parser_service/
│   ├── config.py     # параметры API, ключ и пути
│   ├── api_clients.py # клиенты CoinGecko и ExchangeRate-API
│   ├── storage.py    # кеш и история, атомарная запись
│   └── updater.py    # получение, объединение и сохранение курсов
└── cli/
    └── interface.py  # ввод команд и вывод результатов
```

## Сборка и проверка wheel

```text
uv build
```

Архив исходников и wheel-пакет создаются в папке `dist/`.

Запуск собранного wheel в изолированном окружении из корня проекта:

```text
uv run --isolated --no-project --with ./dist/finalproject_litvyakov_m26_555-0.1.0-py3-none-any.whl valutatrade
```

Имя файла должно соответствовать собранной версии пакета.
При таком запуске также используются `pyproject.toml`, `.env`, данные и логи
из текущей рабочей папки.

Внутри приложения можно проверить обновление и чтение кеша:

```text
update-rates
show-rates --top 2
get-rate --from GBP --to SOL
exit
```
